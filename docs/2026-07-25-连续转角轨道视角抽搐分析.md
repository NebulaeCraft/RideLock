# 连续转角轨道视角抽搐问题分析

- 日期：2026-07-25
- 状态：已完成原因分析，尚未实施修复
- 现象：矿车经过两个连续的转角轨道（直轨 → 转角 → 直轨的小 S 弯， vanilla 普通轨道，非 Railcraft 道岔）时，视角有概率发生抽搐。

## 场景特征

- 轨道布局：两条平行直线轨道之间由一段斜线轨道连接，含两个转角方块（如 SOUTH_EAST / NORTH_EAST），其余为直轨。
- "有概率"对应矿车跨过方块边界、采样窗口推进的时机，而非每次必现。

## 分析结论

### 主因：直轨段拟合方向不恒定 + 每次窗口推进都触发 250ms 过渡动画

1. **直轨上拟合方向并不恒正**：`RailDirectionGeometry.center` 对直轨也只返回方块格心（`.5/.0625/.5`），斜线直轨的采样点带 ±0.5 横向抖动。B 样条拟合（`SmoothTrackCurve.fit`，`SMOOTHNESS_WEIGHT=4.0`、`CONTROL_POINT_SPACING=8.0`）在直轨段会残留小幅"波浪"，方向不严格等于 ±1。窗口每前进一格，波浪相位平移一次。
2. **方向采样的零阶保持混叠**：`SmoothTrackCurve.directionAt`（SmoothTrackCurve.java:106）只对 4 格间距的 tangent sample 做 NLERP，不感知"同一条直轨"，每帧方向带采样相位残差（几度内）。
3. **每代新曲线都重置过渡**：`RideLockHandler.onClientTick`（RideLockHandler.java:88-96）中 `path.blocks()` 每变一格就重新拟合并 `curveGeneration++`；渲染端（RideLockHandler.java:127-139）检测到新代后以 250ms smoothstep 从当前朝向收敛到新目标。矿车高速时每秒数次触发，表现为持续、时序不均的小幅抖动——即主观上的"抽搐"。
4. **概率性来源**：若 `curveGeneration` 不变（速度慢或窗口未推进），`directionAt` 沿固定样条连续求值，视角平滑；跨过方块边界时才抖，故呈概率性。

### 放大因素：过弯处投影最近点的非物理跳变

- `projectArcLength`（SmoothTrackCurve.java:120-138）对整条曲线做**全局最近点搜索**。S 弯处两段直线物理上互相靠近，拟合圆化后更近；矿车在弯中某侧时最近点可能跳到另一侧，切线瞬时反向/横摆，量级接近 90°，表现为偶发明显顿挫。

### 辅助因素：曲线模式与 fallback 模式的边界 flap

- `hasEnoughContext()` 不满足（chunk 边界、窗口过短）时 `clearFittedCurve()`，渲染立刻切回 `applyMovementFallback`。两套 yaw 来源不同（拟合切线 vs 帧间位移方向），边界附近来回切换产生跳变。通常非主因，轨道加载边缘会叠加。

## 建议的排查/修复方向

1. 在 `SmoothTrackCurveTest` 增加斜线直轨测试（如沿 (1,0,1) 逐块推进格心），断言窗口中段 `directionAt` 的 yaw 误差 < 0.1°。若不过：增大 `SMOOTHNESS_WEIGHT`、缩短 `CONTROL_POINT_SPACING`，或显式检测共线点直接返回直线。
2. 构造"直-转-直"小 S 弯测试，遍历弯心附近矿车位置，断言 `projectArcLength` 最近点连续、不跳到另一侧。
3. 工程缓解：
   - `directionAt` 对 horizontal 分量加低通/死区，或 `horizontalSquared` 接近 1 时直接取水平主轴方向；
   - 过渡动画只在目标朝向变化超过阈值时重置计时，而非每代重置。
